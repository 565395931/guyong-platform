# 本地商业化与身份系统路线

本目录记录客服平台从开发环境走向可交付本地产品时的身份、授权和渠道运行设计。账号认证与商业授权必须分离：账号回答“谁可以进入”，授权回答“客户购买了哪些功能”。

## 第一阶段：单机单业主账号（已完成）

- 当前产品与验收范围仅覆盖桌面端，不规划移动端页面或移动端适配。
- 默认模式为 `single_owner`。
- 空数据库首次打开登录页时，只允许创建一个管理员。
- 创建成功后初始化接口自动锁定。
- 后端公共注册默认关闭；没有注册页面。
- 单账号模式隐藏并封锁系统账号管理。
- 管理员可以在登录后修改密码。
- 忘记密码时，在部署机双击项目根目录的 `reset-admin-password.bat`，通过本机数据库恢复；不提供万能密码或远程后门。

开发环境现有的 `admin / admin123` 仅用于本机调试。正式交付必须由客户首次设置密码，或使用一次性初始密码并要求立即修改。

## 第二阶段：离线商业授权（预留）

使用由厂商私钥签名、客户端内置公钥验证的授权文件。建议字段：

- `license_id`、客户名称、产品版本；
- 生效与到期时间；
- `max_seats`、允许设备数；
- 可用渠道与模块，例如 WhatsApp、抖音、拼多多；
- 可选的安装实例 ID 或设备绑定策略；
- 签名算法、密钥版本和数字签名。

授权文件不能包含厂商私钥，也不能依赖可被客户修改的明文开关。身份登录失败与授权失效需要使用不同提示和恢复路径。

## 第三阶段：团队账号（预留）

保留现有 `admin / supervisor / agent`、启用/禁用、账号管理代码。未来以 `AUTH_MODE=team` 开启团队版时：

- 账号只能由管理员创建或邀请，仍不开放公共注册；
- 支持席位上限、角色权限、会话撤销和审计记录；
- 禁用账号或修改密码后，应使既有会话立即失效；
- UI 根据权限隐藏无关能力，服务端始终进行最终鉴权。

## 第四阶段：渠道容器按需运行（预留）

MySQL、Redis 属于基础设施，随主平台启动。WAHA 等仅服务特定渠道的容器由渠道接入页面按需管理：

1. 用户选择接入 WhatsApp；
2. 后端检查 Docker、离线镜像、端口和授权；
3. 用户确认后启动对应容器；
4. 页面展示启动、二维码绑定、在线、异常和停止状态；
5. 停止容器不删除会话数据卷，删除数据必须二次确认。

浏览器不得直接访问 Docker Socket。所有容器操作必须经过本机后端的白名单服务，只允许预定义镜像、Compose 文件和容器名称，并写入审计日志。

## 交付与恢复（预留）

- 安装器生成唯一 `installation_id`，但避免使用不稳定硬件信息锁死客户数据。
- MySQL 数据卷、渠道会话卷、配置和授权文件进入备份清单。
- 提供可验证的备份、恢复、迁移和版本升级工具。
- 密码恢复必须在部署机本地执行；远程支持使用一次性恢复码或客户明确授权的临时流程。
- 不在源码、BAT、镜像或数据库初始化脚本中放置通用密码。

## 验收标准

- 新安装只能初始化一次管理员。
- 初始化后注册接口不可用。
- 未登录、普通账号和授权不足时均由服务端拒绝。
- 密码以 bcrypt/Argon2 哈希保存，日志和接口不返回密码哈希。
- 离线环境可以启动、登录、改密、恢复和备份。
- 团队版、授权和渠道容器功能上线前分别补充威胁建模与端到端测试。
