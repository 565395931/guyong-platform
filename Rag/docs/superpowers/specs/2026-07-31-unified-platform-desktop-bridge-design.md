# 统一平台与分布式桌面消息桥设计

日期：2026-07-31

## 1. 目标

系统需要同时解决两个问题：

1. 将当前按平台拆散的侧栏、会话入口和账号入口收敛成两个统一模块，降低坐席操作复杂度。
2. 在部分电商平台只开放订单/售后 API、没有开放普通客服会话 API 的情况下，通过分布式 Windows 桌面消息桥，把不同电脑上登录的官方客服客户端接入同一个中心客服系统。

最终产品由一台中心服务器和若干客服桌面节点组成。中心服务器统一运行前端、后端、MySQL、Redis、AI、消息审核和会话路由；每台客服电脑运行轻量桌面节点，并登录一个或多个平台官方客服客户端。

## 2. 已确认边界

- 所有源代码、部署文件、安装工程和发布物均位于 `E:\project\project\Rag` 下。
- 左侧导航只保留“平台消息”和“客服账号管理”两个一级入口。
- 消息审核在顶部保留独立入口和数量提醒。
- 订单、产品、客户、数据、售后、营销和视频功能移入顶部“业务工具”。
- AI 配置、主题、用户和退出移入顶部“系统设置”。
- 所有平台账号和桌面节点由中心数据库统一管理。
- 平台登录凭据、Cookie 和本地会话不上传中心服务器。
- 平台验证码、扫码、风控验证和登录失效必须由人工处理。
- 不绕过平台安全机制，不尝试规避平台权限、验证码或风控。
- AI 可以自动回复高置信度安全消息；低置信度、可疑内容和异常全部进入人工审核。
- 任何“不回复”决定必须由人工确认。
- 新接入账号默认处于观察模式，不能立即自动发送。

## 3. 平台能力结论

当前系统已经具备中心会话、AI 回复、消息审核、人工接管和发送状态存储。缺少的是部分平台的双向客服消息传输通道。

平台接入按以下优先级选择：

1. 官方客服 API、官方机器人权限、官方插件或 SDK。
2. 平台允许的浏览器扩展或客户端插件。
3. Windows UI Automation 无障碍接口。
4. OCR 只读识别作为降级能力，不依赖固定坐标自动点击。

抖店开放平台明确说明普通飞鸽会话消息接口尚未开放，但存在飞鸽 API 及“三方客服 / 客服机器人”定向能力。系统应保留官方接入升级路径：

- https://op.jinritemai.com/docs/question-docs/96/6260
- https://op.jinritemai.com/docs/api-docs/188

淘宝旧旺旺聊天记录接口已经下线，官方提供替代的旺旺聊天消息服务，并存在千牛智能客服相关接口。淘宝/千牛优先尝试申请官方能力，桌面消息桥作为拿不到权限时的受控通道：

- https://developer.alibaba.com/support/announcementDetail.htm?id=25584&source=search
- https://developer.alibaba.com/docs/api.htm?apiId=48631

## 4. 总体架构

系统采用“中心控制面 + 分布式边缘节点”。

### 4.1 中心控制面

中心服务器负责：

- 统一前端和身份认证。
- MySQL 和 Redis。
- 会话、消息、订单与账号数据。
- AI 生成、RAG、翻译和回复校验。
- 入站消息审核和人工审核队列。
- 桌面节点注册、心跳、租约和命令调度。
- 入站消息去重及出站发送状态机。
- 权限、审计、告警和配置。

### 4.2 桌面节点

每台需要登录平台客服账号的 Windows 电脑安装一个桌面节点。节点由两个进程组成：

- `Bridge Service`：Windows Service，负责开机启动、中心连接、加密队列、升级、心跳和命令持久化。
- `Bridge Desktop`：当前登录用户会话中的托盘程序，负责识别和操作官方客服客户端。

拆分原因是 Windows Service 位于 Session 0，不能可靠访问用户桌面。服务进程不得直接模拟用户界面。

### 4.3 网络连接

- 桌面节点主动建立到中心服务器的 WSS 长连接。
- 客服电脑无需开放入站端口，适用于 NAT 和普通办公网络。
- 初次安装使用一次性配对码注册，成功后签发节点身份凭据。
- 后续连接使用节点证书或等价的短期签名凭据。
- 所有命令带全局幂等 ID、账号租约版本和过期时间。

## 5. 桌面平台适配器

每个平台作为独立插件实现统一契约：

```text
detectClient()
detectAccounts()
watchMessages()
readConversation()
sendMessage()
healthCheck()
requestLogin()
```

适配器不得依赖硬编码屏幕坐标作为主要方案。优先使用 UI Automation 元素树、事件订阅、窗口标识和可访问性属性。

### 5.1 入站识别

适配器需要输出标准化消息：

- 平台代码。
- 平台账号标识和本地账号指纹。
- 外部会话标识。
- 外部消息标识；平台不提供时生成稳定内容指纹。
- 客户标识和显示名称。
- 消息类型、正文、媒体引用和时间。
- 当前窗口和客户端版本信息。
- 识别可信度及识别方式。

低可信度 OCR 结果不能进入自动回复，只能进入人工核查。

### 5.2 出站发送

发送前必须逐项校验：

- 当前窗口属于目标平台和受支持版本。
- 当前登录账号与租约账号一致。
- 当前聊天对象与中心命令一致。
- 最新客户消息摘要与中心上下文一致。
- 输入框和发送控件状态正常。
- 没有验证码、登录失效、风控、限流或遮挡弹窗。

发送后必须在聊天记录中验证回显内容或取得官方发送确认。未确认时返回 `uncertain`，中心不能显示“已发送”。

### 5.3 异常策略

以下状态一律停止自动操作并转人工：

- 客户端版本或 UI 结构未知。
- 账号标识不一致。
- 无法确认聊天对象。
- 验证码、扫码、风控提示或登录过期。
- 平台限流、禁言或发送失败。
- 本地队列损坏或中心租约失效。
- 同一账号在另一节点取得新租约。

## 6. 节点与账号租约

一个平台账号同一时间只能绑定一个有效桌面节点租约。

### 6.1 数据模型

新增中心表：

- `bridge_nodes`：节点身份、设备名称、版本、状态、最后心跳和能力摘要。
- `bridge_account_bindings`：渠道账号、节点、传输模式、外部账号指纹、租约版本、租约到期时间和登录状态。
- `bridge_commands`：出站命令、目标节点、目标账号、状态、尝试次数、确认信息和失败原因。
- `bridge_events`：节点状态、安全事件、登录事件、版本变化和人工操作审计。

现有 `channel_accounts` 继续作为中心账号主记录，不复制平台凭据。桥接绑定通过外键关联账号主记录。

### 6.2 租约规则

- 节点心跳续租。
- 租约到期后账号标记为离线，未完成命令停止派发。
- 系统不自动把账号转移到其他电脑。
- 新电脑接管必须完成平台登录、账号指纹匹配和人工确认。
- 接管生成新的租约版本；旧节点的延迟命令全部拒绝。
- 中心可查看所有节点，但只有管理员和主管可以接管或解除绑定。

## 7. 消息和 AI 流程

### 7.1 入站

1. 桌面适配器发现客户新消息。
2. 本地队列持久化标准化消息。
3. Bridge Service 通过 WSS 上传。
4. 中心验证节点、租约、账号和幂等 ID。
5. 消息进入现有公共入站服务。
6. 消息审核模块执行硬规则和 AI 分类。
7. 安全高置信度消息进入正常会话与 AI 回复流程。
8. 可疑、低置信度、模型异常和 OCR 低可信度消息进入人工审核队列。

### 7.2 出站

1. AI 或人工产生回复。
2. 中心创建 `bridge_commands`，状态为 `queued`。
3. 命令只派发给持有当前账号租约的在线节点。
4. 节点校验本地账号和会话。
5. 节点执行发送并验证结果。
6. 中心收到 `sent`、`failed`、`blocked` 或 `uncertain`。
7. 只有 `sent` 才将中心消息标记为已发送。

### 7.3 AI 模式

每个平台账号支持：

- `observe`：只同步消息，不发送。
- `assist`：AI 生成建议，人工确认发送。
- `guarded_auto`：高置信度安全回复可自动发送，其余进入人工审核。

不存在无审核边界的完全自动模式。观察模式升级必须由管理员确认，并通过该账号的入站识别与出站回显测试。

## 8. 统一前端

### 8.1 左侧导航

左侧仅保留：

- `平台消息`
- `客服账号管理`

侧栏从顶部到底部使用稳定的深色背景。选中背景严格限制在当前菜单项容器内，不允许延伸到内容区、相邻菜单或页脚。

### 8.2 顶部导航

- `消息审核`：独立图标和待审核角标。
- `业务工具`：订单、产品与报价、客户、数据看板、售后分析、主动营销、视频生成和其他业务模块。
- `系统设置`：AI 配置、主题、用户和退出。

现有路由保留重定向，避免旧书签立即失效，但不再出现在侧栏。

### 8.3 平台消息页

页面提供：

- 平台选择：全部、WhatsApp、微信客服、抖店、拼多多、淘宝/千牛、1688。
- 平台账号选择。
- `客服会话`与`订单/售后事件`视图。
- 官方 API、桌面桥在线、桌面桥离线、需要登录、受限等状态。
- 统一会话列表、聊天窗口和辅助面板。

无客服通道的平台在桥接完成前只显示业务事件；桥接上线后自动开放客服会话。

### 8.4 客服账号管理页

页面统一管理：

- 多个 WhatsApp 账号。
- 多个微信客服账号和企业主体。
- 多个抖店、拼多多、淘宝/千牛和1688账号。
- 账号绑定节点、登录状态、传输方式、AI 模式、最后心跳和发送能力。

页面包含：

- `账号`
- `桌面节点`
- `连接日志`

微信客服的企业凭据、保护策略和白名单保留在微信账号详情中，不再占用独立侧栏入口。

## 9. 安全与隐私

- 中心不保存平台密码、Cookie 或可复用客户端会话。
- 本地敏感状态使用 Windows DPAPI 加密。
- 配对码一次性、短有效期、使用后立即失效。
- 节点身份可在中心吊销。
- WSS 命令同时校验节点身份、账号租约和命令签名。
- 日志不记录客户正文、访问令牌、Cookie 或平台密码。
- 本地截图仅在显式诊断模式保存，默认关闭并设置短期清理策略。
- 所有自动回复继续经过现有消息审核规则。
- 平台能力必须在账号页面准确展示，不得把订单 API 描述成客服消息 API。

## 10. 安装与发布

新增目录：

```text
E:\project\project\Rag\desktop-bridge\
E:\project\project\Rag\shared-protocol\
E:\project\project\Rag\central-deployment\
E:\project\project\Rag\installers\
E:\project\project\Rag\release\
```

现有 `rag-server` 和 `platform-web` 保持原位置，避免无必要的全仓迁移。

### 10.1 中心安装包

`客服中心服务器安装.exe` 负责：

- 检查中心端口和系统要求。
- 安装或连接 MySQL、Redis。
- 安装后端和静态前端服务。
- 注册 Windows Service。
- 初始化数据库和管理员。
- 生成中心证书和节点配对能力。
- 提供升级、备份和卸载入口。

数据库只运行在中心电脑。桌面节点不能直接连接数据库。

### 10.2 节点安装包

`客服桌面节点安装.exe` 负责：

- 安装 Bridge Service 和 Bridge Desktop。
- 配置中心地址和一次性配对码。
- 注册开机启动和托盘程序。
- 安装平台适配器。
- 设置仅出站网络规则。
- 支持签名升级包和失败回滚。

卸载默认保留诊断日志但删除节点身份和本地加密队列；卸载前未上传消息必须明确提示管理员。

## 12. 验收标准

### 统一界面

- 左侧只显示两个一级入口。
- 旧平台路由可重定向到新页面。
- 侧栏无串色、重叠和横向溢出。
- 管理员可在同一页面管理多个 WhatsApp 和其他平台账号。

### 多电脑

- 至少三台电脑可同时绑定不同平台账号。
- 所有消息在一个中心前端出现。
- 回复自动路由到持有目标账号租约的电脑。
- 同一账号不能被两台电脑同时发送。
- 节点掉线后前端在心跳窗口内显示离线。

### 消息可靠性

- 重连不会产生重复入站消息。
- 重试不会产生重复出站消息。
- 未收到本地发送确认时，中心不显示已发送。
- 租约切换后旧节点命令无效。

### AI 安全

- 新账号默认观察模式。
- 低置信度和可疑消息进入审核队列。
- OCR 低可信度消息不能自动回复。
- 任何“不回复”决定均由人工确认。
- 验证码、风控和登录异常不能被自动绕过。

### 安装

- 中心和节点均可通过安装包完成部署。
- 节点安装后不需要手工安装开发环境。
- 节点只需要中心地址、配对码和人工平台登录。
- 升级失败可以回滚到上一个可用版本。

## 13. 非目标

- 不逆向平台加密协议。
- 不伪造官方 API 权限。
- 不绕过验证码、登录保护或风控。
- 不保证一个电脑可以同时登录同一平台的多个账号。
- 不在桌面节点部署独立数据库或完整中心系统。
- 不使用无校验的固定坐标脚本进行自动发送。
