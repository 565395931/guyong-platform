# 拼多多商家业务事件接入

## 当前能力边界

系统通过拼多多开放平台官方商家 API 增量同步订单和售后事件。当前官方商家 API 目录没有提供买家客服聊天消息收发接口，因此本系统不会显示拼多多聊天输入框，也不会通过浏览器自动化模拟客服操作。

## 每个店铺所需配置

- Client ID：开放平台应用客户端标识。
- Client Secret：开放平台应用密钥，只在创建账号时提交并加密保存。
- Access Token：该店铺单独授权得到的访问令牌。
- Mall ID：该令牌对应的店铺标识，用于账号隔离和人工核对。

每个店铺必须创建独立渠道账号并使用自己的 Access Token。禁止多个店铺共用同一个账号配置。账号列表和详情只显示凭据是否完整及脱敏后的 Mall ID，不回显 Client Secret、Access Token 或原始配置。

## 开放平台权限

应用至少需要订单增量查询与售后增量查询权限，对应接口：

- `pdd.order.number.list.increment.get`
- `pdd.refund.list.increment.get`

请求只发送到固定 HTTPS 网关 `https://gw-api.pinduoduo.com/api/router`，使用 Client Secret 按官方规则生成大写 MD5 签名。密钥、Token、签名和客户资料不得写入业务日志。

## 同步与恢复

- 后台 worker 每 60 秒扫描一次启用状态的 `pinduoduo_commerce` 账号。
- 订单和售后分别保存游标，游标按渠道、账号和资源隔离。
- 新账号第一次从当前时间前 30 分钟开始同步。
- 每个查询窗口最多 30 分钟，每页 100 条，最多读取 100 页。
- 只有全部页面解析成功、全部事件完成入库后才推进游标。
- 接口错误、响应异常、分页异常、事件格式异常或入库失败时，只记录脱敏错误码，游标保持不变，下一轮自动重试。
- 事件按官方业务标识与更新时间生成稳定 ID，重复同步由收件箱唯一键去重。

Access Token 到期或被撤销时，在拼多多开放平台重新授权，然后删除并重新创建对应店铺账号。系统当前不提供凭据回显或在原账号上修改密钥的功能，以避免秘密值从后端再次暴露到浏览器。

## 本机迁移

迁移到其他电脑或服务器时，需同时迁移 MySQL 数据库和服务端加密密钥配置，并确保新机器可通过 HTTPS 访问拼多多官方网关。只复制前端文件不能恢复账号凭据或同步游标。
