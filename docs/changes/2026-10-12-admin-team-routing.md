# Admin 与普通客服团队接待（2026-10-12）

## 本次业务规则

- 当前主系统仅保留 Admin、普通客服两个角色。主管权限全部归 Admin；旧角色只在兼容迁移及拒绝旧角色的测试中保留。历史记录与暂停维护的旧应用未清除。
- Admin 可以创建、停用、重置普通客服账号，并查看接待状态和人数。AI 配置与平台连接管理由 Admin 管理；客服仅收到已绑定渠道账号的基础显示信息，不返回连接配置或密钥。
- 已创建 kefu01、kefu02、kefu03，均启用。密码按用户指定设置，不写入文档、源码或日志。三个账号已绑定当前启用的微信小店。
- 普通客服登录默认在线；未结束的私有/长期接待数量大于零时显示忙碌；在线与忙碌均可分配，按人数从少到多，同数优先分给等待最久的人。未登录、连接断开、手动离线或未绑定渠道账号不参与分配。
- 自动分配待人工池中的未分配会话，按优先级/到达顺序处理，通常在下一次 2 秒扫描内分配。AI 池不会无条件转成人工；无可用客服时留待人工。保留既有每人接待上限，当前三个新账号各为 5；已归档会话不占名额。
- 手动离线可释放现有接待到待人工池，随后重新分配；仍遵循已有离线释放开关。断开连接后有 30 秒宽限；手动离线选择在刷新与重连后保留，重新登录默认开启接待。
- 客服默认进入“我的会话”，只接收自己负责的会话。转交/释放同时修正 claimed_by 与 agent_id，并撤销旧会话房间访问。
- 公共话术作为基础库。每个账号的新增、编辑和删除独立保存，其他人不能读取其个人版本。删除公共话术仅在自己的版本隐藏；恢复公共话术撤销自己的公共库编辑/隐藏，保留个人新增。Admin 可以新增/维护公共库。
- 实际数据库公共话术库原为空，已添加问候、确认需求、核实信息三条基础模板。快捷话术无需选中客户即可维护；输入框的快捷指令查询使用相同的账号隔离接口。
- 新客服默认绑定当前启用渠道账号；通过 ChannelAccount 模型新增的平台账号会绑定当前启用客服。既有手动解绑仍有效，原始 SQL 批量导入需明确维护绑定。

## 主要实现

- system-accounts/teamWorkspace.schema：角色迁移留存旧角色记录、个人话术/公共库覆盖表、分配串行锁与手动离线标记。
- conversation-pool/seatAssignment.service：事务内串行分配、实时连接过滤、渠道绑定/启用校验、接待数与公平排序、分配日志和通知。
- system-accounts/quickReplyPersonalization.service、routes/quickReplies：公共基础库与账号个人覆盖，服务端隔离所有读取和修改。
- Socket.IO：认证使用实时数据库角色、普通客服不加入公共池房间、加入会话需归属与绑定、转交后撤销旧房间访问。
- 前端复用现有 Element Plus：账号入口、Admin 接待状态列、客服状态选择器、个人话术新增/恢复入口与可访问图标按钮。
