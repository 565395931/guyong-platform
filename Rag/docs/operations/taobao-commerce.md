# 淘宝 / 千牛订单与退款接入

## 当前能力边界

系统通过淘宝开放平台官方服务端 API 增量同步多个店铺的订单和退款事件，并统一显示在“淘宝 / 千牛”的业务消息页面。公开服务端 API 不提供适用于独立网页客服系统的买家聊天发送能力，因此本系统不会显示淘宝聊天输入框，也不会通过浏览器自动化模拟千牛操作。

千牛插件内能力、旺旺聊天记录查询能力与公开服务端消息发送 API 不是同一类授权。只有淘宝开放平台以后正式提供并批准相应服务端权限，系统才会新增聊天收发功能。

## 每个店铺所需配置

- App Key：淘宝开放平台应用标识。
- App Secret：应用密钥，只在创建账号时提交并加密保存。
- Session Key：卖家完成应用授权后得到的店铺级会话令牌。
- Seller Nick：授权卖家昵称，用于人工核对账号归属。

每个店铺必须创建独立渠道账号并使用自己的 Session Key。账号列表和详情只显示凭据是否完整及脱敏后的 Seller Nick，不回显 App Secret、Session Key 或原始配置。创建成功后，浏览器会立即清空两个密码字段。

## 开放平台权限

应用至少需要以下官方接口权限：

- 订单增量：`taobao.trades.simple.sold.increment.get`
- 退款增量：`taobao.refunds.receive.get`

请求只发送到固定 HTTPS 网关 `https://eco.taobao.com/router/rest`，按 TOP 规则对排序后的公共参数和业务参数生成 MD5 签名。密钥、Session Key、签名和上游错误正文不得写入业务日志。

淘宝开放平台对 CRM 场景的数据范围有限制。系统不请求明文买家昵称、手机号或详细地址，只保留官方允许的 `buyer_open_uid` / `ouid` 作为店铺内客户识别字段。该标识仍应按客户数据管理，不应导出到无权限的第三方系统。

## 同步与恢复

- 后台 worker 每 60 秒扫描一次启用状态的 `taobao_commerce` 账号。
- 订单和退款分别保存游标，游标按渠道、账号和资源隔离。
- 新账号第一次从当前时间前 30 分钟开始同步。
- 每个查询窗口最多 30 分钟，每页 100 条，最多读取 100 页。
- 订单和退款先读取总数，再从最后一页倒序读取到第一页，降低增量窗口内记录变化造成漏单的风险。
- 同步期间 `total_results` 变化、页记录数不一致或超过 100 页时，当前窗口关闭式失败。
- 只有全部页面解析成功、全部事件完成入库后才推进对应资源游标。
- 接口错误、响应异常、分页异常、事件格式异常或入库失败时，只记录脱敏错误码，游标保持不变，下一轮自动重试。
- 事件按订单号或退款单号与 `modified` 生成稳定 ID，由收件箱按渠道、账号和事件 ID 去重。

Session Key 到期、失效或被卖家撤销时，需要在淘宝开放平台重新授权，然后删除并重新创建对应店铺账号。系统当前不提供凭据回显或在原账号上修改秘密值的功能。

## 本机验证

在 `rag-server` 目录运行：

```powershell
node scripts/verify-taobao-commerce-contract.js
```

该脚本使用两个临时、停用状态的淘宝账号，注入 TOP 形状响应，但使用真实 MySQL 事件收件箱和持久游标。它验证倒序分页、重复写入、退款、畸形响应、API 错误、游标保持和账号隔离，并在结束时按临时账号 ID 清理数据。脚本不会调用淘宝官方网关。

## 迁移到其他电脑或服务器

迁移时需要同时迁移 MySQL 数据库和服务端加密密钥配置，保证新机器能够通过 HTTPS 访问淘宝固定网关，并重新启动后端 worker。只复制前端文件无法恢复店铺凭据、事件收件箱或同步游标。

正式启用前应逐店确认应用权限、Session Key 所属卖家、首次同步时间和账号隔离。没有真实店铺授权时，本机只能证明系统合同和落库流程成立，不能声明淘宝生产数据已经接通。
