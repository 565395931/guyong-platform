## 本轮修改

1. 登录页即可设置中心服务；原先设置仅在登录后的布局中可用。
2. 退出与会话过期保留桌面 `file://.../index.html#/login` 路径，避免跳到不存在的本地 `/login`。
3. 保存新地址后先清除旧登录会话再重载，避免保存 IPC 尚未返回时提前刷新；保存异常可在表单中显示。
4. AI 流式请求、产品图、聊天媒体、文件库、发票和订单附件解析为配置的中心服务地址。
5. Electron 限制导航至应用入口；开发地址比较精确 origin；敏感 IPC 限定主窗口主 frame。
6. 修复 Windows 开发启动 `spawn EINVAL`，统一桌面开发探活的 HTTP 协议；缺本地证书仍可构建。
7. 安装包剔除浏览器构建已经包含的重复 node_modules 与单元测试。
8. 仓库释放预占的流水类型由不合法的 `released` 改为 MySQL ENUM 的 `release`；预占状态仍为 `released`。
9. 已发货重试返回真实 outbox 状态，缺记录为 `unknown`，不再错误地报告回写成功。
10. 旧 `/api/admin` 接口接入数据库态认证，统计/技能限主管和管理员，用户 CRUD 限管理员；目录未知 500 错误不再原样回传内部异常；全局错误日志不再打印完整请求体。
11. 后端默认测试入口显式筛选测试，并在空临时目录、替代数据库和 Redis 配置中运行，避免误调用真实会话或付费模型。

## 上线前必须处理

- **权限边界**：旧 RAG 的知识库/上传/线程/模型接口尚未统一认证；公开注册可创建 active agent；WhatsApp webhook 缺验签；WebSocket 对禁用账号和会话权限的检查弱于 HTTP。
- **出库一致性**：库存扣减、运单写入、订单状态和 outbox 不是同一事务；缺少已付款/已取消的发货资格约束，失败恢复不完整。
- **真实物流回写**：没有实际 writebackAdapter 组装及消费闭环。pending/unknown 不能视为平台已接受运单。
- **依赖**：后端生产依赖审计为 1 高危、4 中危；主前端为 ECharts 1 中危，修复建议涉及主版本升级。本轮未在运行中的后端替换依赖。
- **部署与恢复**：启动时 schema 修改、readiness 与优雅关闭流程不足；旧恢复脚本只验证 marker 表，不能证明完整业务库恢复。
- **商业发布**：未配置 Windows 商业代码签名；尚需正式验收、开源许可证与平台接入授权核对。

8 月 14 日文档有隔离 MySQL 双连接并发、履约和备份演练记录，本轮未重跑；历史回写使用模拟适配器，不能作为真实平台回写证据。参见 `commercial-fulfillment-acceptance.tdd.md`、`backend-safe-tests.md`、`../commerce-channel-capability-matrix.md`。
