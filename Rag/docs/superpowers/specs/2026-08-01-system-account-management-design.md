# 系统账号管理设计

## 目标

在统一工作台的“系统设置”分区新增“系统账号管理”，让管理员在不进入旧后台的情况下维护系统登录账号。页面与现有左侧导航、权限模型和 Element Plus 视觉风格保持一致。

## 范围

- 仅 `admin` 角色可查看入口、访问页面和调用管理接口。
- 展示账号用户名、邮箱、角色、状态、创建时间。
- 支持新增账号、修改角色、启用或禁用、重置密码、删除账号。
- 可管理的角色为 `admin`、`supervisor`、`agent`。
- 新密码最少 6 个字符，由后端使用 bcrypt 加密保存。
- 本期不包含组织架构、复杂权限组、登录审计和批量导入。

## 导航与页面

“系统设置”分区包含：

1. AI 配置
2. 功能模块
3. 系统账号管理

新路由为 `/settings/accounts`，标题为“系统账号管理”，路由角色限制为 `admin`。

页面采用紧凑管理表格：顶部提供账号搜索、角色筛选和“新增账号”；每行提供编辑、重置密码、启用/禁用和删除操作。新增与编辑使用对话框，危险操作使用二次确认。

## 安全边界

- 后端所有账号管理接口必须同时验证有效 JWT 和 `admin` 角色，不能依赖前端隐藏入口。
- 当前登录管理员不能禁用或删除自己。
- 系统必须始终保留至少一个启用状态的管理员；禁止将最后一个启用管理员降级、禁用或删除。
- 用户名唯一且不可在编辑时修改，邮箱有值时必须合法。
- API 响应不得返回密码哈希。
- 删除前检查目标账号存在；数据库关联导致无法删除时返回明确错误，管理员可改用禁用。

## 接口

- `GET /api/v1/system-accounts`：账号列表，支持关键词、角色和状态筛选。
- `POST /api/v1/system-accounts`：新增账号。
- `PATCH /api/v1/system-accounts/:id`：修改邮箱、角色和状态。
- `POST /api/v1/system-accounts/:id/reset-password`：重置密码。
- `DELETE /api/v1/system-accounts/:id`：删除账号。

接口统一返回 `{ success, message, data }`，校验错误为 400，未登录为 401，权限不足为 403，资源不存在为 404，冲突为 409。

## 前端结构

- `src/api/systemAccounts.js`：API 封装。
- `src/modules/systemAccounts/accountRules.js`：角色、状态和表单校验等纯逻辑。
- `src/views/Settings/SystemAccountsView.vue`：账号管理页面。
- `channelNavigation.js` 与路由配置：新增管理员入口。

页面操作成功后刷新列表；接口失败时保留当前表单和列表，并展示后端错误信息。

## 测试与验收

- 单元测试覆盖角色过滤、表单校验、最后一个启用管理员保护和当前账号保护。
- 后端路由测试覆盖未登录、非管理员、管理员成功路径和密码不出现在响应中。
- 前端构建通过。
- 浏览器回归覆盖入口可见、页面加载、新增对话框、编辑/重置/危险操作确认、1024 宽度与移动端无横向溢出。

验收结果：管理员能在统一工作台完成账号全生命周期管理；主管和坐席看不到入口，也无法直接调用接口。
