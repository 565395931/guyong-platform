# 抖店业务事件运维说明

## 当前能力边界

当前版本接收抖店开放平台的订单、售后和商品事件，并在 `channel_event_inbox` 中按渠道、账号和 `msg_id` 去重。抖店开放平台目前未开放飞鸽客服消息收发 API，因此本系统不能读取或发送飞鸽客服消息。

本机使用 dummy 凭据完成回调、权限和界面验收，只能证明本机实现可运行，不代表真实应用、店铺授权、公网网络或生产安全配置已经上线。

## 真实上线前置条件

真实上线必须同时具备：

- 抖店开放平台应用的 App Key 和 App Secret。
- 目标店铺对该应用的有效授权，以及对应的店铺 ID。
- 公网可访问的 HTTPS 域名、有效证书和反向代理。
- MySQL、Redis、后端服务及监控告警的生产部署。

回调路径为：

```text
POST /api/channel/douyin/webhook?account_id=<账号 ID>
```

抖店官方目前每个应用只能配置一个消息推送地址。同一应用授权多个店铺时，必须先规划这些店铺由哪一套环境和哪个渠道账号接收，避免把同一应用的唯一推送地址在测试、预发布和生产环境之间反复覆盖。需要环境隔离时，应规划独立应用或统一入口后的明确路由归属。

## 回调处理

回调处理必须遵守以下规则：

- 使用请求头 `app-id`、账号 App Secret 和未经重排的原始 UTF-8 请求体校验 HMAC-SHA256 `event-sign`。
- `tag=0` 是地址探针，签名通过后返回成功，但不写入业务事件表。
- 验签和店铺归属检查通过后，在 2 秒内返回 `{"code":0,"msg":"success"}`，业务事件随后异步落库。
- 使用抖店 `msg_id` 做幂等处理；平台重推同一正文时仍返回成功，但数据库只保留一条事件。
- 验签失败返回 401，店铺 ID 与账号不匹配返回 409，二者都不得落库。
- 订单号、商品号等平台标识可能超过 JavaScript 安全整数范围，解析时必须按无损字符串保存。

## 凭据安全

App Secret 只在创建账号时提交，并以加密配置保存在数据库中。账号列表、账号详情、日志和运维文档不得回显 App Secret、完整 App Key、JWT、`event-sign` 或解密后的配置。生产环境必须通过密钥管理服务注入凭据和加密密钥，不得写入源码、启动脚本或文档。

管理员和主管可以管理抖店账号；管理员、主管可以查看全部业务事件。坐席只能查看与自己有效绑定的账号事件。事件列表不返回 payload，事件详情仅返回经过字段限制和脱敏的结构化 payload。

## 迁移电脑或环境

迁移前需要备份并安全转移：

- MySQL 数据库，至少包括 `channel_definitions`、`channel_accounts`、`channel_event_inbox`、`seat_account_bindings` 和用户数据。
- Redis 持久化数据，以及项目需要保留的日志、知识库、上传文件和媒体文件。
- `DB_HOST`、`DB_PORT`、`DB_NAME`、`DB_USER`、`DB_PASSWORD`、`REDIS_HOST`、`REDIS_PORT`、`REDIS_PASSWORD`、`REDIS_DB`、`JWT_SECRET`、`ENCRYPTION_KEY` 和 `PLATFORM_CREDENTIAL_KEY` 等环境变量。
- 公网域名、HTTPS 证书、反向代理配置、防火墙规则和监控配置。

`ENCRYPTION_KEY` 必须与原环境一致，否则已保存的抖店凭据无法解密。迁移完成后需要重新确认公网回调地址、应用唯一推送地址的环境归属、店铺授权状态、探针 ACK、正式事件去重和权限隔离。不要把本机 LAN 地址或 `localhost` 配置到真实抖店应用。

## 上线检查

1. 在生产密钥管理系统中配置数据库、JWT、加密密钥和抖店凭据。
2. 创建抖店账号，确认页面仅显示“已配置”而不回显凭据。
3. 将公网 HTTPS 回调地址配置到正确的抖店应用，并确认没有覆盖其他环境。
4. 验证官方探针在 2 秒内 ACK 且不入库。
5. 使用已授权测试店铺验证正式事件、重复推送、错签名和错店铺场景。
6. 验证管理员、主管及绑定/未绑定坐席的事件可见范围。
7. 确认飞鸽客服消息收发仍保持禁用，不把业务事件接入误认为客服链路已上线。
