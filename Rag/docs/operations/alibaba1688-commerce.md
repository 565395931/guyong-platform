# 1688 订单与退款接入

## 当前能力边界

系统通过 1688 开放平台官方服务端 API 增量同步多个店铺的加密场景订单和退款事件，并统一显示在“1688 / 业务消息”页面。公开服务端 API 当前不提供适用于独立网页客服系统的买家聊天发送能力，因此系统不会显示 1688 聊天输入框，也不会通过浏览器自动化模拟旺旺操作。

旺旺插件、消息统计或 CRM 工作台能力不等于公开服务端聊天发送 API。只有 1688 开放平台以后正式提供并批准相应服务端权限，系统才应新增聊天收发功能。

## 每个店铺所需配置

- App Key：1688 开放平台应用标识。
- App Secret：应用密钥，只在创建账号时提交并加密保存。
- Access Token：卖家完成应用授权后取得的店铺令牌。
- Seller Member ID：授权卖家的 1688 Member ID，用于请求和人工核对归属。

每个店铺必须创建独立渠道账号并使用自己的授权。账号列表和详情只返回凭据是否完整及脱敏后的 Seller Member ID，不回显 App Secret、Access Token 或原始配置；创建成功后浏览器立即清空两个秘密字段。

## 开放平台权限

应用至少需要以下官方接口权限：

- 加密场景卖家订单：`com.alibaba.trade:alibaba.trade.ec.getOrderList.sellerView-1`
- 订单退款列表：`com.alibaba.trade:alibaba.trade.refund.queryOrderRefundList-1`

请求只发送到固定 HTTPS 网关 `https://gw.open.1688.com/openapi/param2/{version}/{namespace}/{apiName}/{appKey}`，按 param2 规则使用 HMAC-SHA1 签名。App Secret、Access Token、签名和上游错误正文不得写入业务日志。

订单请求始终设置 `needBuyerAddressAndPhone=false`、`needMemoInfo=false` 和 `isHis=false`。入库前再次递归删除联系人、电话、地址、实名、登录 ID、支付宝 ID、备注和反馈字段，只保留 `buyerOpenUid` 作为店铺内客户识别字段。客户隔离键应使用 `channel + accountId + buyerOpenUid`，不得跨应用或跨店铺猜测合并。

## 同步与恢复

- 后台 worker 每 60 秒扫描一次启用状态的 `alibaba1688_commerce` 账号。
- 订单和退款分别保存游标，游标按渠道、账号和资源隔离。
- 新账号第一次从当前时间前 30 分钟开始同步。
- 每个查询窗口最长 30 分钟，每页 20 条，最多读取 100 页。
- 订单页码从 1 开始；退款页码从 0 开始并核对响应页码。
- 全部页面先完成解析和总数校验，再写入事件收件箱。
- 只有全部事件成功写入或确认重复后才推进对应游标。
- 鉴权、响应、分页、规范化或入库失败时只记录脱敏错误码，游标保持不变并在下一轮重试。
- 事件以订单号或退款单号和修改时间生成稳定 ID，由收件箱按渠道、账号和事件 ID 去重。

Access Token 失效或授权被撤销时，需要在 1688 开放平台重新授权，然后删除并重建对应店铺账号。系统当前不提供凭据回显或在原账号上编辑秘密值的功能。

## 本机验证

在 `rag-server` 目录运行：

```powershell
node scripts/verify-alibaba1688-commerce-contract.js
```

脚本使用两个临时、停用状态的 1688 账号，注入官方形状响应，但使用真实 MySQL 事件收件箱和持久游标。它验证多页、重复写入、退款、隐私清洗、畸形响应、API 错误、游标保持和账号隔离，并在结束时按临时账号 ID 清理数据。脚本不会调用 1688 官方网关。

## 迁移到其他电脑或服务器

迁移时必须同时迁移 MySQL 数据库和服务端加密密钥配置，保证新机器能够通过 HTTPS 访问 1688 固定网关，并重新启动后端 worker。只复制前端文件无法恢复店铺凭据、事件收件箱或同步游标。

正式启用前应逐店确认应用权限、Access Token 所属卖家、Seller Member ID、首次同步时间和账号隔离。没有真实店铺授权时，本机验证只能证明系统合同和落库流程成立，不能声明 1688 生产数据已经接通。
