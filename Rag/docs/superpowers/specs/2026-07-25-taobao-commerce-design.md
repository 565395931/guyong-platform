# 淘宝 / 千牛商家业务接入设计

## 目标

在现有聚合客服系统中增加多个淘宝店铺账号，使用淘宝开放平台官方接口同步订单和退款事件，并把官方提供的 `buyer_open_uid`、`ouid` 保留为后续客户画像的稳定身份依据。

## 官方能力边界

- 订单使用 `taobao.trades.simple.sold.increment.get`。官方已将 CRM 场景从老的 `taobao.trades.sold.increment.get` 迁移到不包含消费者敏感信息的简版接口。
- 退款使用 `taobao.refunds.receive.get`。
- 固定 HTTPS 网关为 `https://eco.taobao.com/router/rest`。
- 两个接口都需要卖家授权后的 Session Key。
- 订单接口单次修改时间跨度不能超过一天，官方建议 30 分钟以内；系统统一使用 30 分钟窗口。
- 淘宝公开服务端 API 目录没有提供适用于本独立网页系统的买家客服聊天收发接口。旺旺聊天记录查询或千牛插件内能力不等于服务端消息发送能力，系统不显示聊天回复框。

## 账号模型

每个淘宝店铺保存一份独立配置：`appKey`、`appSecret`、`sessionKey`、`sellerNick`。后端强制使用 `taobao_commerce` 适配器，加密保存配置，列表和详情只返回凭据状态与脱敏卖家昵称，不返回原始配置或 Session Key。

## 同步模型

订单和退款分别使用 `channel_sync_state` 游标，新账号从当前时间前 30 分钟开始。固定窗口内按官方建议倒序分页；任何签名、接口、响应形状、分页、规范化或入库错误都只记录脱敏错误码，不推进游标。事件按业务 ID 与 `modified` 生成稳定 ID，由 `channel_event_inbox` 去重。

订单只请求业务所需字段，包括交易号、状态、金额、修改时间、子订单、`buyer_open_uid` 和 `ouid`。退款只请求退款号、交易号、状态、金额、原因、商品、修改时间与官方开放身份字段，不请求已回收的明文买家昵称、手机号或详细地址。

## 前端

侧栏增加可展开的“淘宝 / 千牛”，包含业务消息和管理员账号管理。业务消息复用现有事件页，只展示订单和退款；账号表单的 App Secret 与 Session Key 使用密码输入且提交后清空。页面明确说明聊天能力边界和 `buyer_open_uid/ouid` 的客户识别用途。
