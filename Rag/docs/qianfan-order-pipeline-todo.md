## A. 数据完整性（会影响采集内容的多少）

1. **订单分页未覆盖**：订单列表 20 条/页，总数超一页时只采当前页并记告警。
   做法二选一：点页大小下拉切到 50/100；或翻页循环采集（注意每次点击都要走自愈流程）。
2. **商品明细与金额缺失**：列表页不含商品（名称/数量/单价）、订单金额、支付方式。
   需要做**订单详情页采集**（点开订单 → 抓详情 → 返回列表），再补写 `order_items`
   与金额字段（`goods_amount`/`deal_amount` 等）。
3. **运单号/发货仓/商家名称只进了 `raw_payload`**：未写 `order_shipments`
   （列表页没有承运商/配送类型信息，建议与第 2 项详情页采集一起做）。
4. **`payment_status` 是推断值**：目前"非草稿一律 paid"。退款/关闭场景未区分
   （原文与上下文都在 `raw_payload` 里，可追溯）。

## B. 联调与验证（上线前建议跑一遍）

5. **端到端 WS 闭环未组合实测**：节点与服务端同时在线的「定时采集 → 上报 → ack 回执 →
   入库」完整链路。组件各自已验证（信封过服务端协议校验、入库服务真实写库、节点上报方法有效），
   组合验证步骤：启动平台与节点（设 `QIANFAN_ORDERS_ENABLED=1`），把 `QIANFAN_ORDERS_AT`
   临时设成一个刚过去的时间点，看到节点日志「入库确认：新增 N 条」即闭环。
6. **锁屏/睡眠下的采集行为未验证**：仅实测了"后台可读、最小化不可读"。
   建议这台机器不锁屏；验证后再决定是否要处理。
7. **千帆冷启动预热复测**：Chromium 无障碍树首次启用是异步构建的（飞鸽需约 15s），
   千帆未复测；探针已用"连续两次节点数一致"兜底。
8. **千帆聊天的字段复测**：会话列表项（昵称/未读/摘要）、消息区、右侧客户面板
   需要**有真实会话在场**才能捕捉；容器 `farmer-contact-list` 已定位，当前无会话。

## D. 运维（与平台长期稳定相关）

11. **MySQL80 服务建议改手动启动或卸载**：`D:\MySQL\Server80` 是 9月25日前的遗留实例，
    今天开机自动拉起后抢占 3306，导致平台 Docker MySQL 无法绑定端口、平台起不来。
    已临时停掉（`net start MySQL80` 可恢复），但**每次重启会复现**。
12. **节点常驻部署**：设置 `QIANFAN_ORDERS_ENABLED=1`、`QIANFAN_ORDERS_AT=HH:MM`
    并让它开机常驻（当前是手动启动）。
13. **`scripts/cleanup_tables.js` 清理**：文件里硬编码了数据库密码兜底值
    （`process.env.DB_PASSWORD || '...'`），违反仓库自身的凭据规则，建议移除兜底值。
