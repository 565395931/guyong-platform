# Codex 项目默认规则

本仓库是计划部署到云服务器的多渠道接入网关。除非用户在当前对话中明确覆盖，Codex 每次处理本项目都遵守以下规则。

## 工作习惯

- 修改完成后在最终回复说明：改了什么、影响范围、验证方式、未验证项和部署/重启要求。
- 完成代码、配置、文档或脚本修改后，追加 `memory/YYYY-MM-DD.md` 当天记录；没有当天文件时创建。
- 不主动启动常驻服务、连接真实平台、发起 OAuth 授权、刷新生产 token、修改云服务器或调用真实发送接口，除非用户明确要求。
- 安装依赖、Docker、数据库写入、云资源、密钥轮换、生产回调配置和数据清理前，先说明影响并取得确认；静态检查和只读查询除外。

## 上下文读取顺序

1. 所有任务先完整读取本仓库 `PROJECT_RULES.md`。
2. 涉及历史决策或重复故障时读取 `memory/MEMORY.md`。
3. 查询近期修改时只读取相关的 `memory/YYYY-MM-DD.md`，不要一次加载全部历史。
4. 涉及专题设计时先读 `docs/README.md`，只加载匹配当前任务的文档。

## 与 Rag 项目的跨项目查询

本项目与 `D:\project\Rag` 是上下游关系。涉及以下内容时，必须对 Rag 项目进行定向只读查询：

- 标准消息字段、消息类型、账号 ID、用户 ID 和时间戳格式。
- rag-server 的消息接收入口、渠道适配器、幂等规则和发送命令需求。
- WebSocket 认证、重连、ACK、状态事件或本地离线恢复。
- 新渠道接入后是否会影响会话池、AI 路由、翻译、媒体或前端展示。

查询顺序：

1. 读取 `D:\project\Rag\AGENTS.md`，遵守 Rag 项目的读取和操作限制。
2. 读取 `D:\project\Rag\PROJECT_RULES.md`。
3. 通过 `D:\project\Rag\docs\README.md` 选择相关专题文档。
4. 需要历史背景时再读取 `D:\project\Rag\memory\MEMORY.md` 或相关日期记录。
5. 最后用 `rg` 定向检查 `rag-server/src/modules/channel-adapters`、`messaging`、`websocket` 和相关路由，以当前代码为最终真值。

- 默认只读查询 Rag 项目；除非用户明确要求同时修改两个项目，不得改动 `D:\project\Rag`。
- 不要一次加载 Rag 的全部文档或每日记忆。
- 发现两项目契约不一致时，先报告差异和兼容方案，再决定修改哪一侧。

## 项目记忆

- `memory/MEMORY.md` 保存稳定架构决策、跨项目契约和复用经验。
- `memory/YYYY-MM-DD.md` 保存每日修改记录。
- 不创建第二套记忆目录。
