# 电商渠道适配器设计

日期：2026-07-25

## 目标

在现有统一会话、渠道账号、订单、售后、客户和 AI 能力上，依次接入 CSV 中的抖店、拼多多、淘宝/千牛、1688、小红书、快手和微信小程序。每个平台只开放官方明确支持的能力，不用页面自动化冒充官方客服 API。

## 已确认的实施顺序

1. 抖店：先接订单、退款、商品等官方消息推送；飞鸽客服收发消息在官方 API 未开放前标记为不可用。
2. 拼多多：接入官方订单增量、售后增量和消息服务订阅状态；当前官方商家 API 目录没有买家客服聊天收发接口，因此客户消息收发标记为不可用。
3. 淘宝与千牛：作为一个授权域处理，淘宝开放平台负责订单/退款，千牛负责商家工作台能力。
4. 1688：接入消息、订单、商品和物流。
5. 小红书千帆：接入资质审核后可用的消息、商品和订单能力。
6. 快手小店：接入消息、订单和商品能力。
7. 微信小程序客服：作为微信生态辅助入口，不与企业微信“客服1号”混用。

## 架构

每个平台实现独立适配器，负责官方鉴权、验签、事件解析、API 错误映射和能力声明。适配器输出统一事件结构，业务事件进入订单/售后流水，真正的客户消息才进入统一会话。账号密钥继续加密存储在 `channel_accounts.config`，前端永不回显完整密钥。

渠道能力分为：

- `customer_messages_in`：接收客户会话消息。
- `customer_messages_out`：向客户发送会话消息。
- `order_events`：订单创建、支付、发货和完成事件。
- `after_sales_events`：退款、退货和售后事件。
- `product_events`：商品状态事件。
- `requires_public_callback`：需要公网 HTTPS 回调。

前端只对声明为可用的能力显示操作按钮。未获得平台凭据时显示“待授权”，官方没有开放的能力显示“平台未开放”，两者不得混淆。

## 抖店首期数据流

1. 管理员在抖店账号页填写账号名称、App Key、App Secret 和店铺 ID。
2. 后端加密保存凭据，返回脱敏信息和专属回调地址。
3. 抖店向回调地址 POST 事件数组，请求头包含 `event-sign` 和 `app-id`。
4. 后端用原始请求体计算 HMAC-SHA256 签名并进行常量时间比较。
5. 回调在两秒内返回 `{ "code": 0, "msg": "success" }`，事件异步进入内部处理。
6. `tag=0` 仅作为地址探测；订单、退款和商品事件写入统一渠道事件表，使用 `msg_id` 去重。
7. 抖店不产生客服会话，也不允许 AI 或人工向飞鸽发送消息，直到官方开放对应 API。

## 拼多多首期数据流

1. 管理员在拼多多账号页填写账号名称、Client ID、Client Secret、Access Token 和店铺 ID；每个店铺使用独立访问令牌。
2. 后端按照拼多多开放平台规则，对公共参数和业务参数按键名排序，使用 `MD5(clientSecret + key1value1... + clientSecret)` 生成大写签名。
3. 后端只访问固定 HTTPS 网关 `https://gw-api.pinduoduo.com/api/router`，不接受前端传入网关地址。
4. 订单通过 `pdd.order.number.list.increment.get` 按更新时间增量拉取；售后通过 `pdd.refund.list.increment.get` 增量拉取；单次时间窗口不超过 30 分钟。
5. 同步成功后才推进各账号、各资源的持久化游标；失败保留旧游标，下一轮重试，避免漏单。
6. 订单事件使用订单号与更新时间生成稳定事件 ID，售后事件使用售后单 ID 与更新时间生成稳定事件 ID，继续由 `channel_event_inbox` 负责幂等落库。
7. 拼多多首期不产生客户会话，也不允许 AI 或人工向平台发送客服消息。`pdd.pmc.*` 是开放平台消息服务订阅管理，不等同于买家客服聊天。

## 数据与安全

- 新增 `channel_event_inbox` 保存事件 ID、渠道、账号、事件类型、业务主键、状态和脱敏后的结构化载荷。
- `UNIQUE(channel, account_id, external_event_id)` 保证平台重推不重复处理。
- 日志不记录 App Secret、访问令牌、完整客户联系方式或原始签名。
- 回调必须校验账号状态、`app-id` 和签名；校验失败仍返回明确的非成功响应，不写入业务表。
- 未配置公网回调前可以用合同测试和本机测试入口验证，不对外宣称已上线。

## 前端

左侧导航延续微信/WhatsApp 的展开模式。每个电商平台包含“业务消息”和“账号管理”；只有支持真实客户会话的平台才显示“客户会话”。账号页使用紧凑表格展示授权状态、能力、回调状态和最近事件，不使用模拟账号数据。

## 验收

- 官方测试消息能够通过签名校验并返回抖店要求的响应。
- 错误 App Key、错误签名和篡改正文均被拒绝。
- 同一 `msg_id` 重推只保存一次。
- 抖店订单/退款事件可在业务消息页查看。
- 抖店页面明确显示“飞鸽客服 API 未开放”，不会出现虚假的回复按钮。
- 现有 WhatsApp、企业微信保护策略和统一会话不发生回归。
