# 客服渠道可展开导航设计

**日期：** 2026-07-24  
**状态：** 用户已确认  
**范围：** 现有 `platform-web` 应用壳内的导航、路由和渠道会话入口

## 1. 目标

企业微信客服不再隐藏在名为“平台账号”的独立入口中。所有客服渠道继续共用同一套登录、主导航、会话、客户、订单和产品数据；每个渠道在左侧导航中使用可展开菜单。

首个完整菜单结构：

```text
统一会话

微信客服  ▾
  微信会话
  客服账号

WhatsApp  ▾
  WhatsApp 会话

订单管理
产品与报价
客户管理
数据看板
主动营销
视频生成
功能模块
```

只显示已经存在真实页面或真实接口的子项，不为未开发平台创建可点击的空壳入口。

## 2. 导航行为

- 使用 Element Plus `el-sub-menu` 实现展开和收起，保持现有侧栏折叠能力。
- “会话工作台”更名为“统一会话”，继续显示所有渠道消息。
- “微信客服”是一级可展开菜单，不再使用含义模糊的“平台账号”名称。
- 微信客服展开后包含：
  - “微信会话”：复用现有会话工作台，并固定筛选 `channel=wecom_kf`。
  - “客服账号”：打开现有企业连接、多客服账号和安全策略页面。
- WhatsApp 先显示真实可用的“WhatsApp 会话”。只有真实账号管理页面可用后才增加“账号管理”；不能把当前模拟页面作为正式功能暴露。
- 侧栏收起时，一级渠道图标仍可打开悬浮子菜单。

## 3. 路由

新增语义清晰的路由：

- `/wecom/conversations`
- `/wecom/accounts`
- `/whatsapp/conversations`

兼容规则：

- `/platform-accounts` 重定向到 `/wecom/accounts`。
- `/workbench` 保留为统一会话。
- 渠道会话路由复用同一个 `WorkbenchView`，通过路由元数据或查询参数设置渠道，而不是复制一个聊天页面。

刷新页面和直接输入地址时必须保留所选渠道；从渠道会话切回统一会话时必须清除渠道限制。

## 4. 权限

- 所有已登录客服可看到“微信客服”及“微信会话”。
- `admin`、`supervisor` 可看到“客服账号”。
- `agent` 不显示账号管理子项，也不能通过直接输入 URL 绕过后端权限。
- 菜单权限只改善界面；企业连接和账号策略仍由现有后端接口鉴权。

## 5. 页面状态

- 微信消息适配器尚未接入时，“微信会话”显示渠道专属空状态，不显示 WhatsApp 离线提示作为微信状态。
- 企业连接尚未创建时，“客服账号”继续显示新增企业主体入口。
- “客服1号”的生产保护规则保持不变，导航调整不能触发账号同步、发送或企业微信后台设置变更。
- 页面标题和面包屑使用“微信客服 / 微信会话”或“微信客服 / 客服账号”，让用户明确当前位置。

## 6. 组件边界

- 新建纯数据导航配置模块，按用户角色生成可见菜单，便于单元测试。
- `AppSidebar.vue` 只负责渲染菜单和展开状态，不在模板内散落角色判断。
- `WorkbenchView` 从路由读取固定渠道，并把它传入现有会话查询和渠道筛选控件。
- `PlatformAccountsView` 继续负责企业连接和客服账号，不复制业务逻辑。

## 7. 验收

- 左侧明确出现可展开的“微信客服”。
- 展开后能看到“微信会话”和管理员可见的“客服账号”。
- 点击两个子项都留在同一个应用壳和同一套登录状态中。
- 旧 `/platform-accounts` 地址自动进入新微信客服账号页面。
- 微信会话不会混入 WhatsApp 会话；统一会话仍可查看全部渠道。
- `agent` 看不到账号管理，管理员和主管可见。
- 侧栏展开、收起、1280px 桌面和 820px 窄屏下无文字重叠。
- 现有企业连接、目录、消息和生产构建测试保持通过。

## 8. 非目标

- 本次不实现企业微信回调、消息同步或正式发送。
- 本次不启用“客服1号”AI。
- 本次不把尚未实现的平台做成可点击占位应用。
- 本次不重写会话工作台，只增加可靠的固定渠道入口。
