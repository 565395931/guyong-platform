# 企业微信真实公网回调上线设计

**日期：** 2026-08-07  
**状态：** 已确认，待书面审阅  
**范围：** `thelonelybrave.cn`、杭州阿里云 ECS、`wehook`、`rag-server`、`platform-web`

## 1. 目标

在不向公网直接暴露宿主电脑的前提下，把企业微信“微信客服”的真实回调、消息同步和受保护文本回复接入现有客服聚合平台。

上线后的最小闭环是：

1. 管理员在本机平台保存企业主体凭据并同步微信客服账号。
2. 企业微信通过公网 HTTPS 回调通知杭州 ECS。
3. ECS 通过受限 SSH 反向隧道把回调转发到本机 `wehook`。
4. `wehook` 验签、解密并调用 `sync_msg` 拉取完整消息。
5. `rag-server` 幂等保存客户消息，人工客服从聚合工作台回复文本。
6. 回复经 `wehook` 调用企业微信 `send_msg`，并回写发送状态。

首次联调只使用独立“AI测试客服”和测试客户白名单；“客服1号”及其他生产账号保持生产保护和 AI 关闭。

## 2. 当前条件

- 企业微信核心代码链路已经存在：企业主体、凭据加密、账号同步、运行配置发布、回调验签解密、`sync_msg`、文本发送、幂等与状态回写。
- 本机运行 `platform-web:3003`、`rag-server:3001`、`wehook:8787/8788` 和 Redis。
- 阿里云杭州有一台运行中的 ECS，可承担公网 HTTPS 入口。
- 旧域名 `wecom.thelonelybrave.cn` 当前没有 DNS 解析，HTTPS 不可访问。
- 该域名此前被企业微信拒绝，原因为备案主体与企业微信认证主体不一致。
- 当前 MySQL 中没有企业微信连接或客服账号记录，真实接入从新增企业主体开始。

## 3. 范围与非目标

本次包括：

- `thelonelybrave.cn` 完成与企业微信认证主体一致或官方认可关联主体的 ICP 备案。
- `wecom.thelonelybrave.cn` 的 DNS、HTTPS 证书和 Nginx 回调代理。
- ECS 到本机 `wehook:8788` 的受限 SSH 反向隧道。
- 企业主体创建、凭据验证、客服账号同步和运行配置发布。
- 企业微信后台回调 URL 验证与真实入站、人工文本出站联调。
- 重复回调、隧道中断、无效签名、白名单拦截和回退验证。

本次不包括：

- 图片、语音、视频或文件的二进制下载与发送。
- 自动扩大到生产客服账号或取消“客服1号”保护。
- 把企业微信凭据、平台登录态或核心业务数据库迁移到 ECS。
- 直接把宿主电脑端口映射到公网。
- 在首次真实链路验收前启用 AI 自动发送。

## 4. 架构

```text
企业微信官方平台
  -> https://wecom.thelonelybrave.cn/webhooks/wecom/<callbackKey>
  -> 杭州 ECS：DNS / HTTPS / Nginx / 限流
  -> ECS 127.0.0.1:18788
  -> 受限 SSH 反向隧道
  -> 宿主电脑 127.0.0.1:8788（wehook）
  -> WebSocket 127.0.0.1:8787
  -> rag-server 127.0.0.1:3001
  -> platform-web 客服聚合工作台
```

边界规则：

- ECS 只承担公网入口和加密转发，不保存 CorpID Secret、Callback Token、EncodingAESKey 或平台登录凭据。
- 宿主电脑主动连接 ECS；公网不能直接访问宿主电脑的 `3001`、`3003`、`8787` 或 `8788`。
- ECS 上的反向隧道端口只绑定 `127.0.0.1:18788`，仅本机 Nginx 可访问。
- Nginx 只代理 `/webhooks/wecom/`，不代理管理 API、前端或调试入口。
- 企业凭据只在本机管理页面录入，由 `rag-server` 加密保存并通过加密运行配置发布给本机 `wehook`。

## 5. 域名与 HTTPS

固定公网入口：

```text
https://wecom.thelonelybrave.cn/webhooks/wecom/<callbackKey>
```

启用条件：

1. `thelonelybrave.cn` 的 ICP 备案主体必须与企业微信认证主体一致，或已完成企业微信认可的关联主体关系。
2. `wecom.thelonelybrave.cn` 的 A 记录指向杭州 ECS。
3. HTTPS 证书必须覆盖 `wecom.thelonelybrave.cn`，证书链完整且未过期。
4. HTTP 只允许跳转 HTTPS，不接受明文回调。
5. ECS 安全组只开放业务所需的 `80/443`，SSH 管理口限制来源；`18788` 不对公网开放。

备案未通过前，不创建对外可用的真实回调配置，也不尝试绕过企业微信的主体校验。

## 6. 隧道设计

首次联调使用 SSH 反向隧道：

```text
ECS 127.0.0.1:18788 -> 宿主电脑 127.0.0.1:8788
```

安全约束：

- 使用专用密钥，不复用管理员日常 SSH 密钥。
- ECS 上为隧道创建独立低权限系统账号。
- 该账号禁止交互式 Shell、PTY、代理转发和任意命令，只允许指定的远程端口转发。
- SSH 服务端关闭 `GatewayPorts`，保证 `18788` 只能绑定回环地址。
- 宿主电脑使用受控服务维持隧道，断线后指数退避重连，开机后自动恢复。
- 隧道日志只记录连接状态和错误码，不记录请求正文或任何密钥。

在首次闭环验收后，如果持续运行对稳定性要求提高，可单独评估 WireGuard；本次不同时引入两套隧道方案。

## 7. 配置与数据流

### 7.1 企业主体与账号同步

1. 管理员登录本机客服聚合平台。
2. 新增企业主体，录入连接名称、CorpID、微信客服 Secret、Callback Token 和 EncodingAESKey。
3. 后端加密保存凭据并生成不可猜测的 `callbackKey`。
4. 管理员执行“验证并同步”，后端调用企业微信官方接口验证凭据并同步 `open_kfid` 账号。
5. 新同步账号默认锁定、AI 关闭、白名单开启；“客服1号”固定为生产保护。

### 7.2 回调配置

1. Nginx 和 SSH 隧道健康后，管理员获得该连接的回调 URL。
2. 管理员从本机平台发布运行配置，使 `wehook` 获得该连接的 Callback Token、EncodingAESKey 和 `callbackKey`。
3. `rag-server` 只有在 `wehook` 返回相同连接和版本的应用确认后，才把连接标记为运行中。
4. 在企业微信后台填写回调 URL，并使用同一组 Callback Token 和 EncodingAESKey 完成 GET 验证。
5. 回调验证成功后，立即执行一次受控测试回调；在此之前 AI 保持关闭。

### 7.3 入站消息

1. 企业微信向公网回调地址发送通知。
2. `wehook` 先验证签名和接收方，再解密回调。
3. `wehook` 使用通知中的 token 调用 `sync_msg`，按游标拉取完整消息。
4. 消息标准化为 `wecom_kf` 入站事件，通过现有网关交给 `rag-server`。
5. `rag-server` 使用稳定事件 ID 幂等落库并 ACK。
6. `wehook` 仅在 ACK 成功后推进同步游标。

### 7.4 人工文本回复

1. 已分配到该客户的坐席在聚合工作台发送文本。
2. `rag-server` 创建唯一命令 ID，通过网关发送到 `wehook`。
3. `wehook` 校验连接、账号状态、保护模式和目标白名单。
4. 通过后调用企业微信 `send_msg`，并把 accepted、sent 或 failed 状态回写平台。
5. 重复命令 ID 返回原结果，不再次调用官方接口。

## 8. 权限与密钥

- `admin`：新增企业主体、替换凭据、验证同步、发布和停用运行配置。
- `supervisor`：查看连接和账号；仅在运行配置停用后维护非生产测试账号的策略与白名单。
- `agent`：只能处理其有权访问的客户会话，不能进入企业连接管理接口。
- Secret、Callback Token 和 EncodingAESKey 保存后不再返回前端。
- 回调、代理和应用日志不得记录凭据、解密后的回调正文、access token 或客户消息全文。
- ECS 不接收本机数据库备份、浏览器登录态或企业微信明文运行配置。

## 9. 失败处理

- 备案或企业微信主体校验失败：停止域名接入，不绕过校验。
- DNS 或证书失败：不配置真实回调，连接不进入运行中。
- SSH 隧道中断：Nginx 返回不可用，监控告警；AI 保持关闭，不改走其他未授权出口。
- 回调签名、接收方或密文校验失败：返回 `400`，不调用 `sync_msg`，不记录正文。
- `sync_msg` 游标不前进：停止继续分页，记录同步错误，不推进成功游标。
- `rag-server` ACK 失败：事件保留为待重试，不标记处理成功。
- 账号锁定、生产保护、目标不在白名单或文本为空：发送前直接阻断。
- 企业微信 API 错误：记录脱敏错误码并把消息标记失败，不无限重试。

## 10. 监控与审计

管理页必须能看到：

- 网关连接状态。
- 企业连接状态和健康状态。
- 最近账号同步时间。
- 最近回调、最近入站和最近出站时间。
- 脱敏后的最近错误说明。

ECS 必须监控：

- DNS 与证书有效期。
- Nginx `2xx/4xx/5xx` 数量和限流命中。
- SSH 隧道服务存活和本地 `18788` 可连接性。
- 磁盘、内存和系统时间同步。

所有连接、验证、发布、停用、账号策略和白名单修改保留操作人及时间审计记录。

## 11. 验收测试

### 11.1 基础设施

- DNS 解析到杭州 ECS。
- HTTPS 证书链有效，HTTP 自动跳转 HTTPS。
- 公网无法访问 ECS `18788`，Nginx 本机可以访问。
- 公网无法直接访问宿主电脑业务端口。
- 隧道服务重启后可以自动恢复。

### 11.2 管理链路

- 管理员能新增企业主体、验证凭据并同步至少一个独立测试客服账号。
- 前端和 API 响应不包含 Secret、Token 或 EncodingAESKey。
- 发布运行配置后，Rag 与 `wehook` 显示相同连接和版本。
- 普通坐席访问连接管理接口返回 `403`。

### 11.3 回调与消息

- 企业微信 GET 回调验证成功。
- 白名单测试客户发送文本后，平台只生成一条消息和一条会话关联。
- 相同回调重复发送不会生成重复消息。
- 非法签名、错误接收方和篡改密文均被拒绝。
- 人工文本回复只发送一次，并正确显示 sent 或 failed。
- 非白名单客户、锁定账号和“客服1号”发送均被阻断。

### 11.4 故障与回退

- 主动停止隧道后，外部回调失败但内部服务和历史数据保持完整。
- 恢复隧道后，待处理事件按官方同步机制恢复且不重复入库。
- 停用运行配置后，管理页显示已停用，发送被阻断。
- 企业微信后台停用回调后，不再产生新入站事件。

## 12. 上线顺序

1. 完成或修正 ICP 备案主体。
2. 配置 DNS、证书、ECS 安全组和 Nginx。
3. 配置专用 SSH 隧道账号、密钥和宿主电脑持久服务。
4. 从公网和本机分别验证端口暴露边界。
5. 在本机平台新增企业主体并同步账号。
6. 选择独立“AI测试客服”，准备一个测试客户 `external_userid` 白名单。
7. 发布运行配置并确认 `wehook` 应用成功。
8. 在企业微信后台完成回调验证。
9. 完成真实入站和人工文本出站测试。
10. 完成重复、失败、断链和回退测试。
11. 保持 AI 关闭，观察运行健康；AI 自动发送作为后续独立变更评审。

## 13. 回退顺序

发生异常时按以下顺序回退：

1. 在本机平台停用企业连接的运行配置，并等待 `wehook` 确认。
2. 在企业微信后台停用或移除该回调 URL。
3. 停止宿主电脑 SSH 隧道服务。
4. 保留企业主体、账号映射、会话、消息和审计记录用于排查。

回退不得删除连接数据、替换加密密钥、解除生产账号保护或开启未验证的备用出口。
