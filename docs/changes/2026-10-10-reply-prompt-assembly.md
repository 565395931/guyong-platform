# 默认提示词模板与客服上下文组装

## 实现
- AI配置保存按钮旁新增“默认提示词模板（非技术人员不要改动）”，只读弹窗显示服务端同一份DEFAULT_REPLY_TEMPLATE，包含默认客服原则与JSON决策规则。页面业务提示词保留原值，填写后位于内置模板之前。
- replyProtocol是内置协议源，replyContext统一组装。每次请求一份system：业务提示词、默认客服原则、场景语言/安全指令、JSON协议；不会把系统规则作为历史反复插入。
- messages顺序：system → 最近N条user/assistant历史 → 本轮参考资料+客户当前消息。历史文本预算24000字、请求整包500KB；图片历史保留，超过总包限制明确提示。参考资料去重，最多5条、每条3000字，测试总10000字、正式场景沿用4000字预算。预算单位是字符，不宣称精确Token数。
- 每轮重新检索百炼，测试检索结合最近两条客户问题处理“它”等追问；不使用历史AI答案作检索事实依据。原始当前客户消息作为返回userMessage进入历史，当前参考资料不持久化进历史。
- 测试与正式客服推荐/自动回复共用默认规则及历史/资料组装。正式已落库当前客户消息从历史尾部去重，避免双发当前问题。质检/情绪等内部任务自定义协议保留。
- 删除旧默认提示词中“没资料输出空内容”规则。JSON正常回复、追问、转人工仍由严格后端解析，格式不合法不把原始JSON或错误当客户回复；人工状态调整仍是前一待办，未提前实施。

## 验证
- 后端634项、前端179项通过，前端生产构建通过。浏览器验证模板按钮、只读弹窗和JSON示例可见。
- 真实本地测试两轮：基础款紫外线99%、追问可见光70–75%；第二轮contextCount=2，两轮各命中5条，返回userMessage不含参考资料。
- 正式generateRecommendationStream真实联合检索验证action=reply，仅输出99%客户文本，历史中的本轮消息去重后消息总数2。测试未发送真实客户消息，不更改用户已保存业务提示词、模型或密钥。后端已重启。

## 为何每轮仍发送system
当前Chat Completions无状态，供应商不自动保存会话，第一次发送后不再携带无法保证规则存在。固定system置于首部便于供应商前缀缓存，但是否命中/优惠以真实usage为准；将规则放入历史也仍需每次上传，且会被上下文条数截断。
官方依据：https://api-docs.deepseek.com/guides/multi_round_chat/ 和 https://api-docs.deepseek.com/guides/kv_cache/

## 后续：模板可编辑
用户要求模板可编辑后，弹窗改为草稿编辑、独立保存和恢复默认（填回草稿，保存后生效）；取消有修改时确认放弃，请求中禁止关闭，失败保留草稿。管理员专用接口保存ai_default_reply_template，模型测试与正式客服生成均读取该模板；后台action/reply/reason解析结构仍固定。用户业务提示词继续放在模板前。后端636项、前端179项、构建通过；浏览器验证编辑、取消继续编辑、恢复默认、空模板实际后端校验和模拟保存后重新打开回显。模拟文本没有写入实际配置，后端已重启。
